# Breakwater — extended wave campaign and cannon-origin ballistics (2026-10-16)

## User request and scope

The user requires *dramatically more waves* and wants the actual firing/aiming trajectory to originate at the cannon, snapping to the controller ray only after the selected weapon's physical firing arc has been exceeded. The work affects the game-private `mrcalzon02/ReverieVR` branch `main` only, not ReverieVR Home, host input, global binding profiles, shaders, or Save/ABI formats. No GitHub Actions were used.

## Observed before changes

`Campaign::waves_this_period` capped each day/night period at eight and opened Cadet at 2 daytime + 1 nighttime waves. `breakwater_module.cpp` drew an actual three-dimensional cannon but fed regular `CombatTarget`, projectile-to-sphere, cover interception, miss splash, and the recorded tracer from `input.pointer_origin`. Consequently the visible barrel and the computed projectile had **different starting points** (gun muzzle vs controller), even while the weapon was inside its physical elevation/traverse arc. The missile pod also remained frozen in its default orientation because the existing gun-direction update explicitly excluded the `uses_ghost` mount.

## Implemented

- **Long campaign:** new pure game-private `breakwater_wave_schedule.h` defines `ForPeriod(location,day,night,tier)`. First day: Cadet 12 day / 8 night, Regular 14 / 10, Veteran 16 / 12, Siege 18 / 14. Each subsequent day adds one wave to each period; each new location adds two. Limit 32 per day/night period, well inside the existing uint8_t live wave index / 32-bit save word; **total unique waves across nine days:** Cadet 244, Regular 280, Veteran 316, Siege 352. Per-wave `NextCount()` cap of 10 craft, shore infantry pool, save layout (80-byte v2), shop-between-each-wave, damage and progression state machines remain unchanged.
- **Single firing origin:** `gunmesh::Muzzle` exposes the exact pre-recoil barrel tip from the real model recipe. Game-private `breakwater_cannon_trajectory.h::CannonShot` validates the selected mount's traverse, takes controller *direction* and computes a normalized cannon-*origin* ray. Production `Interact` and `Update` use that ray for regular gun target selection/aim feedback, infantry and cover intersection, actual impact depth, water miss and saved shot-tracer origin/direction. The dashed greenish preview now emerges from the same physical muzzle and follows each mount's actual ballistic gravity while in arc. A round departs the idle muzzle; the existing 90-ms recoil happens **after** launch.
- **Out-of-arc behavior:** `CannonShot` fails closed outside the selected weapon's traverse (also null/nonfinite vectors). Outside the arc, suppress in-arc ballistic preview/target lock, preserve the controller-aligned ghost marker; reject normal gunfire rather than inventing a reachable impact. Special SAM remains intentionally controller-directed for its existing two-step aircraft lock. Within arc, *all five* mounted gun meshes including missile pod follow the controller orientation and shoot from the mount, rather than using a free-floating hand ray. HUD/shop controller interactions still use the original pointing ray.
- **Coverage:** `breakwater_wave_schedule_test.cpp` enumerates every day/night period on all three maps and four difficulty tiers, checks the exact 244/280/316/352 totals, never exceeding 32 waves per period. `breakwater_cannon_trajectory_test.cpp` checks all five muzzle positions, actual gravity and target hit agreement, accepted/rejected traverse, invalid inputs and unchanged outputs for failed cannon firing. Existing `breakwater_campaign_test.cpp` expected counts and late-wave save validation were updated; the day-to-night rollover exercise now seeds a checked late-wave checkpoint instead of replaying every earlier wave. The local visual regression runner includes both new tests.
