# Breakwater 64px generated PNG runtime integration — 2026-11-04

Intent: deliver the six image-generated coastal-defense materials as actual mounted-gun, bunker and battlefield textures inside native Breakwater rather than merely showing a concept sheet. User approved committing all six originals and continuing development.

Assets: six untouched 1254x1254 original PNGs at art/breakwater/source/; game-ready 64x64 RGB565-compatible PNGs below app/src/main/assets/native/breakwater/materials/. The image-to-game conversion is offline Python/Pillow under tools/breakwater/prepare_materials.py, with --verify to compare decoded RGB values. No Pillow dependency is shipped to Android. Surface mapping matches materials::Surface enum: shingle, quay_concrete, black_basalt, oxidized_steel, sandbag_burlap, olive_enamel.

Runtime: game-private breakwater_authored_materials.h reuses the already established omega_front_png.h bounded native decoder. During module Create, the optional host asset reader performs two-phase length/read calls only for six exact allowlisted paths (16 KiB each), checks PNG CRC, 64x64 dimensions and fully opaque alpha. Successful RGBA tiles remain in game-owned CPU buffers. During each GL context creation, BuildSpriteAtlas produces the baseline 128x448 atlas then overlays loaded authored tiles into their six existing 64px cells before a single glTexImage2D. Any missing, invalid, mismatched or transparent tile retains its known-good procedural material; errors are reported as partial admission. Nothing changes per-eye logic, save version, weapon/infantry positions or actual projectile targeting.

Static tests: isolated exact new loader/test compiled under GCC and Clang with -std=c++17 -Wall -Wextra -Wpedantic -Werror, loading all six real optimized PNGs from a local asset tree, checking tile content and missing-tile fallback. This isolated host fixture substituted libpng for the repository's established omega decoder, so it does not yet certify the true decoded runtime module. The existing native-asset-scope regression and Breakwater visual script have source additions for the production decoder and packaged files, **not executed in the full repository**. Android NDK/GLES2, installed APK, actual S9 Daydream binocular appearance and sustained performance remain unverified.

Next: run strict full native regressions including original decoder and asset scope, build the Android module, inspect headset screenshots for inverted UVs, texture seams and repetition (especially stacked sandbag imagery on volumetric bags), then optimize/mipmap only if evidence supports it. The original six generated images remain available in source for revisions without extra generation.
