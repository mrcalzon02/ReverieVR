# Breakwater coastal material pass — 2026-11-04

Intent: replace the most visible flat-color battlefield ground with real PSX-scale surface materials, while preserving the Galaxy S9 single-APK, single-render-pass and seated Daydream input/targeting boundaries. The existing gun silhouettes, imported Beckenburg props, scene lighting and campaign save ABI remain unchanged.

Implementation: a private deterministic four-material atlas extension (shingle, harbor concrete, black basalt, weathered steel), with four 64×64 RGBA tiles built once per GLES context below the existing sprite tiles. Atlas dimensions grow from 128×256 to 128×384 (128 KiB -> 192 KiB RGBA8), with no external decoder, network images, extra GPU texture, or extra draw. The three location-specific central beach heightfields now emit identical positions and UV-mapped triangles into the existing sprite mesh, instead of redundantly drawing flat ground underneath. Shore shoulders, foam, revetments, imported models, target positions and ballistic simulation are untouched. Opaque depth-tested material faces use the same stereo matrices and existing day/night sprite tint.

Static evidence: isolated exact new material header and its regression test compiled and ran under GCC and Clang with C++17 -Wall -Wextra -Wpedantic -Werror. Regression covers determinism, all material tile footprints, bounded UVs and finite vertices for each beach, expected 960 triangles per coast, and invalid-location rejection. The existing verify-breakwater-visuals.sh loop includes that test for subsequent repository runs. The static test is not an Android native module build.

Risks and gates: actual GLES2 rendering, sRGB/texture orientation, texture detail and scale, day/night palette consistency, weapon/UI depth occlusion, S9 stereo frame timing, battery/thermal response and APK packaging remain unverified. This pass adds no new release or GitHub Actions execution. Continue with installed-daydream screenshots and adjust material palettes and tiling after real eye captures.
