  provider. The active download ID, trusted URL, APK digest, package ID, newer
  Android version and persistent signer checks remain mandatory.
- An explicit phone-test release marker now also starts the existing installed
  hub, Android recovery/capture and all-game functional workflows. No duplicate
  workflow or new visual/style release gate is introduced.
- Native admission documentation now describes current bundled-game behavior.

## Attempts repaired and release integrity

The first installed-hub attempt passed 19 of 20 tests. Its sole failure expected
the retired "enable Development logging mode to launch" text. The follow-up
accepts the correct early-access label and explicitly rejects the false logging
requirement, retaining every game inventory, real navigation and whole-app
update-button check. The resulting run passed all 20 tests and its separate
all-17 genuine Android GLES2 framebuffer verification; no test was skipped.

The earlier concurrent #2151 build failed release creation after main advanced
across workflow edits. GitHub's documented workflow authorization check applies
when the requested tag target differs from the default branch in workflow files.
Holding main at the real #2152 build source allowed normal publication. No token
permission was expanded, no tag moved and no earlier APK relabeled as newer
source. The test-only follow-up then passed the release gate with no duplicate
APK build, because the requested release was already fulfilled.

## Demo use and evidence limits

Use **Check ReverieVR updates** and select Phone Test #2152. The direct headset
APK above is also available for an in-place Android installation. Keep the
existing app installed to retain its data. The companion APK is separately
named on the same release page. All 17 native games remain bundled; they need
no individual game downloads or change to Development logging.

[Actual gameplay and Android capture evidence](../gallery/native-games/2026-11-26/demo-beta/README.md)
is preserved with source, capture type and hashes. Host gameplay frames and
Android emulator menu frames are identified separately. Sitka's synthetic
practice bay remains distinct from its real-source geography inspection.

Physical Galaxy S9/Daydream and Galaxy A14 controls, optics, sound and actual
on-device upgrade remain unverified by this remote pass. Host/emulator evidence
must not be described as physical headset testing. The live-feed probe runs the
production selector with published version fixtures; it does not execute Android
DownloadManager or Package Installer. The emulator upgrade uses its own shared
test signer. Independent verification of the public APK establishes the actual
distribution signing lineage and newer version.

The application checks establish their tested parser, routing and lifecycle
behavior, not a new physical-phone DOOM boot, media decode or complete imported
OBJ scene session. Larger campaign, art and world-completion milestones remain
separate from this bounded demo repair. No sustained-performance claim is made.
