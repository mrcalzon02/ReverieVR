# Shared native asset library (version 1)

**Implemented in source; APK/headset acceptance pending.** ReverieVR's common `native/shared/v1/` contains sixteen compact owner-generated surface textures, three curated BWM1 models, and four PSX-style panoramic horizon textures. These are actual reusable *asset bytes*, not an imaginary common GPU texture memory across different native applications. The source-authoritative manifest `shared-assets/catalog-v1.json` gives each asset a stable logical ID, exact relative path, Git blob hash and license/consumer metadata.

## Current runtime contract

- The single ReverieVR APK packages each common file **once**. The host's existing read-only `read_asset` callback resolves it from verified game content or APK baseline; module access is explicitly allowlisted in `reverie_native_shared_asset_catalog.h`. Game IDs outside that opt-in list receive zero access. No new ABI, Java permission, remote endpoint, second APK or dynamic library loader.
- Breakwater currently loads all sixteen authored PNGs into its one 128×768 GLES2 sprite/material atlas (384 KiB RGBA8; one upload per GL context, no additional draw call) and reads the three BWM1 defense prop meshes; its two owner-specific boat/APC models stay game-private. If a shared path is unavailable in an older verified content pack, Breakwater can attempt its historical private name, but the old APK files are no longer duplicated.
- Omega Front now deliberately loads concrete and steel from the same shared PNG paths, eliminating two older distinct material files. Its 2D tactical engine and its other art remain unchanged.
- Red Ledger and the Test Chamber have exact-path access to curated assets but **do not yet have consumers for BWM1 models**; BWM1 is not `.rlprop`, `.obj` or general-purpose glTF. Never display unsupported model loads as working.

## Cross-repository source consumption

Other authorized internal game repos may use this as a **versioned source library**: pin a ReverieVR Git commit and a manifest blob, select only the needed IDs, verify blob bytes, licenses and formats, and materialize them only into the final target build. Do not blindly git-submodule or archive the entire large repository; do not publish purchased full source packs or unlicensed derivatives. A build that imports selected files remains offline at runtime. Cross-repo *source* references alone do not save download space if standalone APKs independently bundle the same bytes.

A future install-once cross-game **runtime** cache would require verified signed shared-pack manifests, immutable content addressed by SHA-256, reference counts, atomic mount/swap/rollback, dependency handling and offline verification before game launch. Android different packages cannot access each other's private storage by path. This cache is **planned, not implemented**, and does not supersede the existing single-APK product rule.

## Acceptance

`python3 scripts/verify-shared-native-assets.py` checks twenty-three exact source files, Git object hashes, available SHA-256, PNG/BWM signatures, bounds, no old duplicate package paths, and reference wiring. `bash scripts/verify-breakwater-visuals.sh` adds the shared verifier to existing Breakwater host tests. Run native asset-scope source regressions, Omega texture asset checks, the existing Android/NDK build and installed headset tests. The two removed Omega PNGs total **14,834 uncompressed source bytes**; compressed APK/network savings are not measured and may differ. No extra draw pass or runtime texture upload is introduced by the shared namespace itself.

The native-doc drift guard now maps both `reverie_native_shared_asset_catalog.h` and `reverie_native_asset_scope.h` to this standard for same-commit source changes, keeping per-game permission expansion reviewable.

The legacy companion **test artifact** now stages all sixteen shared textures, three shared generic BWM1 props, and two owner-private boat/APC models through a Gradle `Sync` task. Its staging output no longer retains old private copies after incremental builds. The existing Android emulator workflow checks all twenty-one exact ZIP asset entries and rejects reintroduced duplicates. Omega Front's historical verified-content fixture includes only its two shared concrete/steel PNGs, maintaining the same **141-file inventory**, not sixteen redundant coastal materials.

The legacy Java `RvPackInstaller` now admits only explicitly enumerated shared paths for four opt-in game IDs, matching the native catalog's material vs. model permissions. This does not add a globally mounted cache, does not grant all games arbitrary shared files, and does not change the one-main-APK release policy. Package recovery remains signed catalog-/digest-verified, per-game, and separate from authoritative native game code. `scripts/verify-shared-native-assets.py` also checks these source and CI wiring invariants. Android emulator completion, final APK ZIP readback and S9 stereo/thermal testing are **not yet observed**.

## Second owner-generated material expansion — 2026-11-04

Ten new owner-directed diffuse tiles (dock planks, mossy seawall, corrugated roof, camouflage netting, diamond-plate deck, trench soil, reinforced concrete, crate planks, riveted bulkhead and beach pebbles) are each committed as an indexed-palette 64×64 PNG alongside the original six in the same `native/shared/v1/materials/coastal/` namespace. They add **33,396 source bytes** before APK compression. Breakwater's bounded existing PNG decoder converts all 16 to RGBA only during native game creation; one enlarged 128×768 GLES2 RGBA atlas (393,216 bytes) is uploaded once per GL-context creation, retaining nearest filtering and no per-eye image decoding, GPU binds or new shader. Every tile is mapped to a real 3D fortification or height-meshed shore region across Shingle Bay, Iron Quay and Blackcap Island: anti-slip battery deck, bunker concrete cheeks, corrugated defensive roofs, sidewall seawall blocks, ammunition crates/camouflage covers, rear steel bulkheads, rear soil and side pebble patches, and dock approach sections. Old procedural fallback remains for damaged/missing tiles and leaves earlier game content valid. These are UV/art-only surface treatments, **not** new cover colliders or gun hitboxes.

The source high-resolution image generation files are preserved outside the APK (conversation assets and the user's Drive folder [Breakwater Shared Material Sources](https://drive.google.com/drive/folders/1Z_vqO-jRM6KVkEXkqpEAlnmPRhwi51fO)). The reusable Git blobs are verified by exact bytes and SHA. New assets extend v1 additively; existing six PNG blobs and three generic model blobs are unchanged. Cross-repository inclusion still requires a pin, format/read-permission review and actual consuming-game implementation. Android/NDK build, installed 16/16 tile load evidence, stereoscopic S9 rendering and performance acceptance are **not** established merely by this source commit.

## Shared 360° horizon panoramas — 2026-11-04

Four user-directed original 1774×887 generated panoramas (Shingle Bay, Iron Quay, Blackcap Island, Stormwatch Point) and archival 1024×512 variants are retained in [Shared VR Horizon Panoramas v1](https://drive.google.com/drive/folders/14eKJ4EY-h3HOIL4gzokFRg6hUWueAAt0). The **actual runtime PNG bytes** live once in the common APK under `native/shared/v1/horizons/` as 512×256 indexed PNGs (total 88,875 bytes); the Git SHA-1, content SHA-256, format, dimensions and consumers are pinned in `shared-assets/catalog-v1.json`. Left/right edges of the runtime panoramas meet for continuous 360° sampling. These are authored artistic panoramas, **not** real photogrammetry, geolocated Sitka mountains, surveyed shoreline polygons, or legally reusable public-domain images.

The reusable, module-independent `reverie_native_horizon_geometry.h` constructs a fixed 32×12, 2,304-vertex unit sphere once per GLES context, with the top 1,152 vertices contiguous for a sky-only option. `reverie_native_horizon_gl.h` loads only these four exact source-approved paths through the host's existing bounded read_asset service and the existing compact PNG decoder. A single small GLES2 texture draw per eye uses camera rotation without camera translation, far-depth sky output, no depth writes, and GL state restore. Missing/invalid optional panorama files retain the older procedural sky in Breakwater rather than stopping gameplay. There is no per-eye PNG decoding or generation, no new native ABI, and no network at runtime.

**Breakwater** now chooses its matching panorama for all four theater IDs and draws 3D mountains, coast, boats, waves, combat and HUD over it; the previous procedurally colored sky remains an offline fallback. **Sitka's unregistered source-only terrain proof** reads only the Shingle Bay atmosphere and draws its *upper hemisphere only*: generic generated mountains/water are never substitutes for source-derived Sitka city terrain or named water polygons. The other named games receive exact-path permission for future approved consumers, **not** a claim that their renderers have been migrated.

Verification: `native_horizon_geometry_test.cpp` covers finite sphere positions, full 360 wrap, UV bounds and 1,152-vertex sky-only hemisphere with host GCC/Clang; `scripts/verify-shared-native-assets.py` checks four additional exact PNG blobs and size/path/consumer rules. Headset stereo, GLES2 shader, decode, screenshot readback, thermal and Android APK build acceptance remain pending until actually executed and observed.
